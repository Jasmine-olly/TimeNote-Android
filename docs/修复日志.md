## FIX-01 前台检测失效：悬浮计时器不显示（最严重）

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证（vivo V2203A / Android 14） |
| **现象** | 进入已勾选的娱乐 App 后，悬浮计时器不出现，也无阈值提醒 |
| **根因** | 无障碍服务用**最后一次窗口事件**的包名当作当前前台。后台窗口（如 MainActivity 自身）状态一变，就覆盖掉真实前台包名；服务误以为前台是 TimeNote，会话从未启动 |
| **修复** | 改用 `getWindows()` 中 `isActive` 的**活动窗口**判断真实前台；无障碍配置加 `flagRetrieveInteractiveWindows` + `canRetrieveWindowContent`（仅取包名，不遍历窗口内容） |
| **验证** | 日志 `active-window -> com.xingin.xhs`，会话正常启动，计时器恢复显示 |
| **涉及文件** | `monitor/TimeNoteAccessibilityService.kt`、`res/xml/accessibility_service_config.xml` |

## FIX-02 前台服务被 ROM 后台清理

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证（vivo） |
| **现象** | 应用退到后台一段时间后，监督服务消失，计时/检测停止（进程因无障碍绑定仍在） |
| **根因** | 国产 ROM（vivo）后台管理会清理前台服务；且原心跳循环若被单次异常打断会静默停摆 |
| **修复** | `onStartCommand` 返回 `START_STICKY`（被系统杀掉后自动重建）；心跳循环包 try/catch，单次异常不再中断 |
| **验证** | 连续运行 2 分钟服务存活；日志 tick 不间断 |
| **涉及文件** | `monitor/FloatTimerService.kt` |

> 注意：START_STICKY 无法对抗用户手动「一键清理」或 ROM 的彻底停止。日常使用需在 vivo「设置→应用→TimeNote→耗电管理/自启动」里放行。

## FIX-03 定时提问到点延迟约 50 秒

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证（Android 14） |

## FIX-07 已汇编日记不包含新增/补答的提问

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证反馈（2026-08-04） |
| **现象** | 日记汇编后，新落地的提问（到点新增）和待回答补答都不会出现在已汇编日记里 |
| **根因** | 日记是「汇编时刻的**静态快照**」：汇编时读取一次回答/娱乐数据生成 Markdown 落库，之后回答记录增改不再回写 |
| **修复** | 新增 `DiaryAutoSync`：回答记录**增 / 改 / 删**时自动重新汇编受影响日期；`Diary` 增加 `edited` 字段（Room **v2→v3** 迁移）——未手动编辑过的日记自动覆盖，手动编辑过的不动 |
| **验证** | 补答后当天日记自动出现该回答（标「补答于」）；改计划问题文本同步刷新；v3 迁移后已有数据完好 |
| **涉及文件** | `diary/DiaryAutoSync.kt`（新）、`data/entity/Diary.kt`、`data/TimeNoteDatabase.kt`、`question/QuestionAlarmReceiver.kt`、`question/QuestionPromptViewModel.kt`、`ui/question/QuestionViewModel.kt`、`data/dao/AnswerRecordDao.kt`、`ui/diary/DiaryViewModel.kt`、`ui/diary/DiaryScreen.kt` |

## FIX-08 「重新汇编」清空手动编辑内容

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证反馈（2026-08-04） |
| **现象** | 手动编辑过日记（天气/小结等）后点「重新汇编」，手工内容被源数据整篇覆盖清空 |
| **根因** | 重新汇编 = 用源数据**整篇重建**正文，不区分「自动生成部分」与「用户手工部分」 |
| **修复** | 改为**小节级合并**（`mergeAutoSections`）：未手动编辑（`edited=false`）整篇重写；手动编辑过（`edited=true`）只替换「娱乐使用」「定时提问」两个数据小节，天气/小结/其他手工内容保留 |
| **验证** | 编辑天气/小结后再补答或重新汇编 → 手工内容保留，仅数据小节刷新为新回答/新统计 |
| **涉及文件** | `diary/DiaryAutoSync.kt`、`ui/diary/DiaryViewModel.kt` |

## FIX-10 已编辑日记的「小结」不随数据刷新

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证（2026-08-04，V1.1 小结增强） |
| **现象** | 手动编辑过的日记，补答 / 重新汇编后「小结」仍是旧文本，新增的回答统计（「完成了 N 条…其中 X 条补答」）不出现；而「定时提问」小节已刷新 |
| **根因** | FIX-08 的小节合并策略只刷新「娱乐使用」「定时提问」，未纳入「小结」；小结是**自动生成的汇总数据**，同样应随回答/娱乐数据更新（真机 DB 取证：`edited=1`，小结停在「完成了 2 条」而实际已答 3 条） |
| **修复** | `mergeAutoSections` 的 `DATA_SECTIONS` 加入「小结」；天气与用户自定义内容仍不在刷新列表，保持不变 |
| **验证** | 重新汇编后小结刷新为「…完成了 3 条定时提问，其中 3 条是补答的」 |
| **涉及文件** | `diary/DiaryAutoSync.kt` |

## FIX-11 前台检测误判系统窗口/小窗导致会话误重置

| 项 | 内容 |
|---|---|
| **阶段** | 真机验证（2026-08-04，F1.2 悬浮计时） |
| **现象** | ① 下拉通知栏/状态栏时计时被打断重置；② 打开「小窗」应用（尤其拉大后）仍会打断计时 |
| **根因** | 无障碍用「活动窗口」判前台，但下拉通知栏/状态栏/输入法是**系统窗口**会被当成前台；vivo 小窗作为应用窗口尺寸不定，固定面积阈值（45%）拉大后仍被当成前台 |
| **修复** | ① 前台判定只认 `TYPE_APPLICATION` 应用窗口，系统窗口不算；② **只有「基本铺满屏幕（面积 ≥85%）」的应用窗口才算真前台**，小窗无论多大只要没铺满就保持上次真实前台，不打断监督；③ 锁屏用 `ACTION_SCREEN_OFF` 接收器显式重置会话（避免「保持前台」导致锁屏不重置） |
| **验证** | 下拉通知栏、任意大小的小窗均不打断计时；真正全屏切走才隐藏；锁屏后解锁计时从 0 重开 |
| **涉及文件** | `monitor/TimeNoteAccessibilityService.kt`、`monitor/FloatTimerService.kt` |

### 关键设计决策（后续实现沿用的约定）
1. **日记 = 自动部分 + 手工部分**：`Diary.edited` 标记；未编辑整篇自动重写，已编辑只合并数据小节，天气/小结/手工内容永不被动覆盖。
2. **封面复用 `cover` 字段**，编码 `"☀️|😊"`，零迁移；封面 = 天气 emoji 大字 + 心情底色。
3. **翻页只翻「有日记」的日期**，空白日跳过，滑动与日历选中双向同步。
4. **前台 = 「基本铺满屏幕（≥85%）的应用窗口」**：系统窗口、任意大小小窗都不算切换前台，保证温柔监督不被打断。
5. ~~演示数据不污染真实库~~：v1.0.0 已移除全部演示数据功能（统计/日记页的「生成…」按钮与底层代码），正式版无测试入口。
6. **导出走 SAF（系统选位置）**：零存储权限、零联网，文件名带时间戳。
7. **治愈手绘风**：奶油纸底 + 暖墨字 + 鼠尾草绿；虚线描边纸签、手绘波浪线、笔记本横线。

### 优化方向（后续可选）
- **封面建议细化**：情绪识别目前关键词匹配，长回答可考虑加权/短语
- **统计增强**：周报/月报改「自然周/自然月」（当前是滚动 7/30 天）；加趋势线、应用排行占比
- **长日记阅读**：整页滚动已够用，可再优化独立滚动
- **治愈风打磨**：更多手绘元素（日历手写感、加载 doodle、卡片描边动画）、深色模式专属校验

### 过程沉淀
- **UI/视觉类问题必须装机看**：波浪线直线、图标效果、月报标签全是真机才暴露（FIX-12/14、图标迭代）
- **大改风格前先确认方向**：手绘线稿图标被否后恢复原样式只改颜色——先给方向/草图再动手，小步迭代
- **演示数据零污染策略（v1.0.0 已移除）**：曾用 Prefs 标志 + 内存合成，验证完一键清除；正式版已删除该功能
- **测试阈值恢复纪律**：临时阈值（1 分钟）用完必须恢复正式值（30/60/90）
- **真机反馈即需求**：每个「现象描述」都直接驱动设计演进（快照→同步、覆盖→合并、小窗→尺寸判定）
- **Kotlin 字符串模板坑**：`$标识符` 后紧跟汉字会被连成同一标识符（如 `"$verb导入完成"` 编译报 Unresolved reference），必须写 `${verb}导入完成`（导入功能踩到）
- **权限要能"合并引导"**：无障碍引导并入「精确检测」开关后，权限页更清爽——一个功能一个入口，避免重复/冲突提示

| **根因** | 三处主线程被系统 UsageStats 查询阻塞：①`FloatTimerService` 每秒心跳每 5 秒在主线程查 6 小时前台事件；②`QuestionPromptViewModel.submit` 在**主线程**同步做日记汇编（`queryUsageStats` / `queryEvents`）；③`QuestionPromptActivity.onCreate` 同步取场景信息 |

| **涉及文件** | `monitor/FloatTimerService.kt`、`question/QuestionPromptViewModel.kt`、`question/QuestionPromptActivity.kt` |
